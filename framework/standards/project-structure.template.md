## 2. Source Code Organization (`src/`)

### 2.1 Principle: Feature-Based or Layer-Based

Choose one pattern and apply consistently:

**Feature-Based (recommended for apps):**
```
src/
├── features/
│   ├── auth/
│   │   ├── components/        # UI components for auth
│   │   ├── services/          # Business logic for auth
│   │   ├── models/            # Data models for auth
│   │   ├── api/               # API endpoints for auth
│   │   └── index.ts           # Public API of this feature
│   ├── dashboard/
│   └── settings/
├── shared/                    # Shared across features
│   ├── components/
│   ├── utils/
│   └── types/
└── index.ts                   # App entry point
```

**Layer-Based (recommended for libraries/SDKs):**
```
src/
├── components/                # All components
├── services/                  # All services
├── models/                    # All data models
├── utils/                     # All utilities
├── types/                     # Shared type definitions
└── index.ts                   # Entry point
```

### 2.2 File Naming
- **Component files:** [PascalCase].tsx — `UserProfile.tsx`
- **Service files:** [kebab-case].ts — `user-service.ts`
- **Model/Type files:** [kebab-case].ts — `user-model.ts`
- **Utility files:** [kebab-case].ts — `date-utils.ts`
- **Test files:** [same-as-source].spec.ts — `user-service.spec.ts`
- **Index files:** `index.ts` — barrel export only, no logic

### 2.3 Directory Depth
- **Maximum depth:** [5] levels from `src/`
- **Flat over nested:** Prefer flatter structures; nest only when [N] files exist in a directory

## 3. Test Code Organization (`tests/`)

```
tests/
├── unit/                      # Mirrors src/ structure
│   ├── services/
│   │   └── user-service.spec.ts
│   └── utils/
│       └── date-utils.spec.ts
├── integration/               # Cross-module tests
│   └── auth-flow.spec.ts
├── e2e/                       # End-to-end tests
│   └── user-journey.spec.ts
├── fixtures/                  # Test data files
│   └── user-data.json
└── helpers/                   # Test utilities
    └── setup.ts
```

### 3.1 Test File Location Rules
- Unit tests: mirror source structure under `tests/unit/`
- Integration tests: `tests/integration/`
- E2E tests: `tests/e2e/`
- Test file names: `<source-file-name>.spec.<ext>` or `<source-file-name>_test.<ext>`

## 7. Module Boundaries

### 7.1 Public API
Every module MUST have a clear public API:
- Use barrel exports (`index.ts`) to define public surface
- Internal implementation details are NOT imported from outside the module
- Cross-module imports only through public API

### 7.2 Dependency Rules
- No circular dependencies between modules
- Shared code goes in `shared/`, not imported across features
- External dependencies declared in project manifest only

### 7.3 Module Size
- **Maximum files per directory:** [20] (consider splitting)
- **Maximum lines per file:** [300] (consider splitting)
- **Maximum exports per barrel:** [30] (consider splitting)
