# Coding Standards Hierarchy (编码规范层级)

## Overview

All agents MUST follow a two-tier standards hierarchy. When tiers conflict, the higher tier **always** takes precedence. For projects with UI, §0.6 (UX规范约定) is also generated at Tier 1.

## Tier 1 (PRIMARY): Project-Level Coding Standard

- **Source:** `docs/coding-standards.md` §0 — generated by Scanner Agent Phase F during initialization
- **Content:**
  - §0.2 公共方法约定 — naming, verb prefixes, async patterns, error handling, parameter conventions
  - §0.3 常量定义约定 — naming (`UPPER_SNAKE_CASE`), type preference (`enum` vs `as const`), location, string prefixes, magic value tolerance
  - §0.4 文件组织约定 — directory/file naming, barrel exports, test co-location, feature structure
  - §0.5 编码风格约定 — indentation, quotes, semicolons, function style, import ordering, null handling, line width
  - §0.6 UX规范约定 (if project has UI) — component naming, styling approach, layout patterns, accessibility, responsive design, design system integration
- **Authority:** Absolute. Project-level conventions override any conflicting generic rule.

## Tier 2 (FALLBACK): Language-Specific Generic Standard

| Language | Standards File |
|----------|----------------|
| JavaScript (ES2022+) | `framework/standards/coding-standards.javascript.md` |
| TypeScript (5.x+) | `framework/standards/coding-standards.typescript.md` |
| Java (17 LTS+) | `framework/standards/coding-standards.java.md` |
| Python (3.11+) | `framework/standards/coding-standards.python.md` |
| Other | `framework/standards/coding-standards.template.md` |

Each standard covers 15 chapters. Rules apply **only where §0 does not specify otherwise**. For polyglot projects, agents load only their language's standard; SE Agent loads all when designing cross-language integration.

## Resolution Rule

```
§0 rule exists → FOLLOW §0 (project convention)
§0 rule absent → FOLLOW generic standard (language convention)
§0 = "mixed" → FOLLOW generic standard, flag inconsistency for remediation
```

## §0.6 UX规范约定 (Project-Level UX Standard)

Generated by Scanner Agent Phase F when the project includes UI code. This section is the authoritative UX reference for all agents working on UI-related tasks.

### Detection Scope

During Phase 0, the scanner detects:
- **UI Framework:** React, Vue, Angular, Svelte, etc. (from package.json dependencies)
- **Component Library:** MUI, Ant Design, shadcn/ui, Element Plus, etc.
- **Styling Approach:** Tailwind CSS, CSS Modules, styled-components, Sass/SCSS, vanilla CSS
- **Layout Pattern:** Responsive breakpoints, grid system, page layout conventions
- **State Management:** Redux, Zustand, Pinia, Vuex, Context API, etc.
- **Routing:** React Router, Vue Router, Next.js App Router, etc.
- **Accessibility:** ARIA usage, keyboard navigation patterns, i18n/i10n libraries
- **Testing:** Testing Library, Cypress, Playwright, Storybook presence

```markdown
#### §0.6.7 UX约束强制项 (Mandatory UX Constraints)
These are mandatory when PRD or Dev Story involves UI design:
- 用户必须提供交互流程说明（页面导航图、用户操作路径）
- 用户必须提供视觉参考或设计稿（Figma/Sketch 链接、线框图、或样式参考）
- 用户必须明确响应式设计需求（支持的设备类型和断点）
- 用户必须提供表单交互规范（验证规则、错误提示、提交行为）
- 用户必须提供反馈机制说明（加载状态、空状态、错误状态的处理方式）
```

### Merge Rules for §0.6

Same as other §0 sections:
- **confirm:** Detected conventions match generic → keep, annotate "✓ confirmed"
- **override:** Project conventions differ → REPLACE, annotate "⚠ project standard overrides"
- **add:** Project-specific UX convention → add as mandatory rule, annotate "⬢ project-specific"

### UX Guidelines Document

If UI is detected, the scanner also generates `docs/ux-guidelines.md` with the full UX convention details. Agents working on UI tasks MUST load this document alongside `docs/coding-standards.md`.
